# Memory Tagging Extension

## Definition

§3.23 defines how the Arm Memory Tagging Extension (FEAT_MTE) interacts with the SMMU. The SMMU has a restricted role: it does not perform tag checking, does not write Allocation Tags, and reserves one MAIR encoding. §3.23.1 defines how FEAT_MTE_PERM changes stage 2 MemAttr interpretation when enabled.

---

## §3.23 SMMU Interaction with MTE

### Reserved MAIR Encoding

The MAIR encoding `0xF0` (Normal memory, Outer Tagged, Inner Tagged — the standard MTE encoding on a PE) is **Reserved** in the SMMU context. Specifically:
- `CD.MAIR0` and `CD.MAIR1` fields in a Context Descriptor must not use `0xF0` as a MAIR attribute entry.
- If `0xF0` appears in a CD MAIR field, the behavior is UNPREDICTABLE.
- This reservation exists because the SMMU does not implement Allocation Tag memory access semantics; treating an access as Tagged would be architecturally incorrect.

### SMMU-Originated Accesses Are Tag Unchecked

All SMMU-originated memory accesses (translation table walks, STE/CD fetches, event queue writes, command queue reads, HTTU atomic updates) are performed as **Tag Unchecked**. The SMMU:
- Does **not** check Allocation Tags on any memory it reads or writes.
- Does **not** write Allocation Tags to any memory location.
- Uses Non-Tagged memory attribute semantics for all its own memory accesses.

This means that even if a translation table is held in Tagged memory (by the OS's view), the SMMU's walks of that table are Tag Unchecked — no tag faults will be generated by SMMU walks.

## §3.23.1 FEAT_MTE_PERM — Stage 2 MemAttr Reinterpretation

`FEAT_MTE_PERM` is a Arm architecture feature (`SMMU_IDR3.MTEPERM==1` indicates SMMU support) that changes how certain stage 2 MemAttr encodings are interpreted when `NoTagAccess` semantics would otherwise apply.

### Rule

When `SMMU_IDR3.MTEPERM==1`, stage 2 MemAttr encodings that encode `NoTagAccess` are **reinterpreted** as NOT having `NoTagAccess` and instead having the same memory type and cacheability as specified by FEAT_MTE_PERM. All accesses are treated as not having the Tagged attribute at stage 2.

### Reinterpretation Table (S2FWB==0)

When stage 2 Force Write-Back (`S2FWB==0`):

| Stage 2 MemAttr Encoding | Normal Meaning | MTE_PERM Reinterpretation |
|--------------------------|----------------|---------------------------|
| `0b0100` | Normal, Inner/Outer Write-Back Cacheable with NoTagAccess | Treated as Normal, Inner Write-Back / Outer Write-Back (no NoTagAccess) |

Other encodings that do not involve `NoTagAccess` are unaffected.

### Reinterpretation Table (S2FWB==1)

When stage 2 Force Write-Back (`S2FWB==1`), the following encodings are reinterpreted:

| Stage 2 MemAttr Encoding | Normal Meaning (S2FWB==1) | MTE_PERM Reinterpretation |
|--------------------------|---------------------------|---------------------------|
| `0b1111` | Normal Tagged | Treated same as `0b0111` (Normal WB-WA-RA) |
| `0b1110` | Normal Tagged (variant) | Treated same as `0b0110` |
| `0b1101` | Reserved | Reserved (unchanged) |
| `0b1100` | Reserved | Reserved (unchanged) |
| `0b10xx` | Reserved | Reserved (unchanged) |

### Behavioral Summary

With FEAT_MTE_PERM active, the SMMU behaves consistently with a system where no accesses carry the Tagged attribute at stage 2 — `NoTagAccess` is effectively suppressed for the affected encodings, and the memory type/cacheability that would have applied without the Tagged qualifier is used instead.

This feature allows software and hypervisors to use stage 2 MemAttr encodings without needing to distinguish between Tagged and non-Tagged variants when configuring guest memory.

### Discovery

- `SMMU_IDR3.MTEPERM==1`: SMMU supports FEAT_MTE_PERM stage 2 MemAttr reinterpretation.
- The feature is applied automatically when the SMMU implements it; there is no per-stream or per-CD enable bit.
