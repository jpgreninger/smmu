# Two-Stage Translation

## Definition

The SMMU supports two independent and optionally-combined stages of address translation:

- **Stage 1:** Translates the incoming Virtual Address (VA) to an Intermediate Physical Address (IPA). Configured per-stream (via the [concepts/context-descriptor.md](concepts/context-descriptor.md)) and optionally per-substream.
- **Stage 2:** Translates the IPA to a Physical Address (PA). Configured per-stream via the [concepts/stream-table-entry.md](concepts/stream-table-entry.md).

When both are enabled the configuration is called **nested**. When only one is enabled the other behaves as bypass (address passes through unmodified). An SMMU must support at least one stage; the absent stage is equivalent to permanent bypass.

## Precise Lookup Sequence

An incoming transaction is processed in the following logical order:

1. **Global bypass check:** If `SMMU_CR0.SMMUEN == 0`, the transaction bypasses the SMMU entirely; attributes are taken from `SMMU_GBPA` (or the transaction is aborted if `SMMU_GBPA.ABORT == 1`).
2. **STE lookup:** The StreamID indexes the Stream table to locate an STE. If the StreamID is out of range or the STE is invalid/disabled, the transaction is terminated and an event recorded.
3. **Stage 2 config:** If the STE enables stage 2 (`STE.Config[1] == 1`), the STE contains `STE.S2TTB` (stage 2 translation table base pointer) and `STE.S2VMID`.
4. **CD lookup (stage 1):** If the STE enables stage 1 (`STE.Config[0] == 1`), a CD is located using `STE.S1ContextPtr` (optionally indexed by SubstreamID). If stage 2 is also enabled, the CD is fetched from IPA space (i.e., the CD address is translated through stage 2). If stage 2 is not enabled, the CD is fetched from PA space.
5. **Stage 1 translation:** The CD's `TTB0`/`TTB1` is walked. The output is an IPA (or bypassed if `STE.S1DSS` causes bypass). Walk addresses for stage 1 are themselves subject to stage 2 translation when nested is configured.
6. **Stage 2 translation:** The IPA is walked using `STE.S2TTB`. Output is a PA.
7. **Output:** The final PA, with memory attributes, is forwarded into the system.

Any step may generate a fault; behavior on fault depends on the [concepts/fault-models.md](concepts/fault-models.md) configuration.

## §3.4 Address Sizes

Three address size concepts:

**IAS (Intermediate Address Size):** Maximum usable IPA generated by stage 1 and input to stage 2. Not a configurable parameter; defined as:

```
IAS = MAX(VMSAv8-32 LPAE ? 40 : 0,  VMSAv8-64/VMSAv9-128 ? OAS : 0)
```

VMSAv8-32 LPAE always supports a 40-bit IPA; VMSAv8-64/VMSAv9-128 limits IPA to OAS. When VMSAv8-32 LPAE is not implemented, IAS = OAS.

**OAS (Output Address Size):** Maximum usable PA output from the last translation stage. Reported in `SMMU_IDR5.OAS`. Must match the system PA size.

**Input address size:** Always 64 bits. Smaller device or interconnect addresses are zero- or sign-extended to 64 bits in a system-specific manner.

**Disabled SMMU bypass:** When `SMMUEN == 0` and `GBPA.ABORT == 0`, input address is passed directly as output PA. If input address exceeds OAS → terminated with abort, no event.

**All-bypass STE** (`STE.Config == 0b100`): If input address exceeds OAS → terminated + F_ADDR_SIZE recorded.

### §3.4.1 Input Address Size and Virtual Address Size (VAS / UAS / TBI)

**VAS (Virtual Address Size):** Determined by `SMMU_IDR5.VAX`:
- `0b00`: 49 bits (2 × 48-bit TTB0/TTB1). This is always the case for SMMUv3.0.
- `0b01`: 53 bits (2 × 52-bit TTB0/TTB1).
- `0b10`: 56 bits (2 × 55-bit for EL1/EL2-E2H StreamWorlds, or 1 × 56-bit for EL3 StreamWorld).

**UAS (Upstream Address Size):** Number of effective address bits presented by the client device.

Three categories based on UAS vs VAS:
1. **57 ≤ UAS < 64**: TBI has meaning — bits VA[63:56] may differ from VA[55]. TBI determines whether Translation fault occurs if they differ.
2. **VAS ≤ UAS < 57**: TBI is meaningless — sign-extension means VA[63:56] cannot differ from VA[55].
3. **UAS < VAS**: Range checks only fail if T0SZ/T1SZ is configured for a smaller range than the presented address. Maximum table configuration covers any presented address.

**VMSAv8-32 LPAE:** Stage 1 uses bits[31:0] as VA. Translation fault if bits[63:32] are not all zero. T0SZ/T1SZ selects TTB0 or TTB1 from upper bits of range.

**VMSAv8-64/VMSAv9-128 range checks:** Input range of N significant bits fails unless `VA[AddrTop:N-1]` are identical:
- TBI disabled: `AddrTop == 63`
- TBI enabled: `AddrTop == 55` — VA[63:56] are ignored; effective VA[63:56] taken as sign-extension of VA[55].

Note: TBI configuration is in the CD — can only be enabled when stage 1 translates. When stage 1 is bypassed or disabled, TBI is always disabled.

Note: Because addresses < VAS bits are zero-extended, VA[55] == 0 and TTB1 is never selected for such addresses.

**Maximum input sizes per translation format:**

| Format | Version | TTB max VA |
|--------|---------|-----------|
| VMSAv8-32 LPAE | Any | 32 bits |
| VMSAv8-64 | SMMUv3.0 | 48 bits (49-bit VA, 2×48) |
| VMSAv8-64 | SMMUv3.1+ | 48 bits (if VAX==0b00, 4K/16K granule without DS), 52 bits (if 64K granule, or DS==1) |
| VMSAv9-128 | SMMUv3.4 | 48 bits (VAX==0b00), 52 bits (VAX==0b01), 55 bits EL1/EL2-E2H (VAX==0b10), 56 bits EL3 (VAX==0b10) |

Note: All input address bits are recorded unmodified in fault event records. If upper address bits are truncated by the interconnect, software must not rely on mis-programmed upper bits to cause a Translation fault; it must check validity of upper bits directly.

### §3.4 Stage 1 Address Checks

When stage 1 translates:
1. **F_TRANSLATION** if VA is outside the range configured by the CD (T0SZ/T1SZ-based range).
2. **F_ADDR_SIZE** if the output address exceeds the effective IPA size:
   - VMSAv8-32 LPAE: IPA fixed at 40 bits (CD.IPS ignored).
   - VMSAv8-64/VMSAv9-128: IPA is effective `CD.IPS` value, capped to OAS.

When stage 1 bypassed (`STE.Config == 0b1x0`, `STE.S1DSS == 0b01`, or unimplemented): input address passes directly to stage 2 as IPA. If it exceeds IAS → F_ADDR_SIZE, terminated with abort.

### §3.4 Stage 2 Address Checks

When stage 2 translates:
1. **F_TRANSLATION** if IPA is outside the range configured by `STE.S2T0SZ`:
   - VMSAv8-32 LPAE: capped at 40 bits.
   - VMSAv8-64/VMSAv9-128: capped to IAS. For SMMUv3.1+ with 52/56-bit IAS: limited to 52 bits, further limited to 48 bits unless S2TG=64K or S2DS=1.
2. **F_ADDR_SIZE** if output exceeds effective PA range:
   - VMSAv8-64/VMSAv9-128: effective `STE.S2PS` (capped to OAS).
   - VMSAv8-32 LPAE: fixed at 40 bits (S2PS ignored). If OAS < 40 and output > OAS → silently truncated.

When stage 2 bypassed: IPA passed directly as PA. If IPA > OAS → silently truncated to OAS. If IPA < OAS → zero-extended.

### §3.4.3 Address Sizes of SMMU-Originated Accesses (CONSTRAINED UNPREDICTABLE)

SMMU-originated accesses (STE/CD/VMS fetches, queue accesses, MSI writes, last-stage table walks) may have out-of-range addresses. Behavior when address exceeds allowed size:

| Access type | Configured by | Address type | Behavior when too large |
|-------------|---------------|--------------|------------------------|
| CD/L1CD fetch | `STE.S1ContextPtr` | stage 1 only → PA | C_BAD_STE (SMMUv3.1+); CONSTRAINED UNPREDICTABLE in SMMUv3.0 (F_CD_FETCH, C_BAD_STE, or truncate) |
| CD/L1CD fetch | `STE.S1ContextPtr` | stage 2 present → IPA | CONSTRAINED UNPREDICTABLE: C_BAD_STE, stage 2 Translation fault (non-truncated), or SMMUv3.0 truncate+continue |
| CD fetch | `L1CD.L2Ptr` | stage 1 only → PA | C_BAD_SUBSTREAMID (SMMUv3.1+); CONSTRAINED UNPREDICTABLE in SMMUv3.0 |
| CD fetch | `L1CD.L2Ptr` | stage 2 present → IPA | CONSTRAINED UNPREDICTABLE: C_BAD_SUBSTREAMID or stage 2 fault |
| STE fetch | `STRTAB_BASE` or `L1STD.L2Ptr` | PA | Truncate to OAS or F_STE_FETCH |
| VMS fetch | `STE.VMSPtr` | PA | C_BAD_STE |
| Queue access | `*Q_BASE` | PA | Truncate to OAS |
| MSI write | `*_IRQ_CFG*` or CMD_SYNC args | PA | Truncate to OAS |
| Last-stage TTB walk | Intermediate descriptor addresses | PA | F_ADDR_SIZE |
| Last-stage TTB walk | Starting TTB from STE.S2TTB or CD.TTBx | PA | STE/CD ILLEGAL |

Note: SMMUv3.0 behavior for oversized CD addresses is CONSTRAINED UNPREDICTABLE. SMMUv3.1+ generates C_BAD_STE or C_BAD_SUBSTREAMID. CONSTRAINED UNPREDICTABLE options are: generate the specific fault, or truncate and continue.

**VA input range:**
- Configurable up to VAS bits; sign-extended from the top significant bit.

**IPA range:**
- Capped to OAS for VMSAv8-64; fixed at 40 bits for VMSAv8-32 LPAE.

**PA output range:**
- OAS as reported in `SMMU_IDR5.OAS`.

## Relationship to PE Translation

SMMU translation table formats are identical to Armv8-A PE formats (VMSAv8-32 LPAE, VMSAv8-64, VMSAv9-128). Tables may be shared between SMMU and PE without modification. The SMMU stage 1 / stage 2 split mirrors the PE EL1 / EL2 hypervisor split: stage 1 for OS-level isolation, stage 2 for VM-level isolation.

## Model Implementation Notes

- A model must handle the case where stage 1 is bypassed but stage 2 is not: in this case the input VA is passed directly to stage 2 as the IPA; an IAS range check is still performed and can generate an F_ADDR_SIZE fault.
- Stage 2 faults during a stage 1 table walk (i.e., the walk address is in IPA space and stage 2 faults on it) are reported as stage 2 faults, not stage 1 faults. The event record differentiates these for hypervisor use.
- A stage 2 fault while fetching a CD from IPA space is also a stage 2 fault.
- TBI (Top Byte Ignore) is only meaningful when stage 1 uses a CD. When stage 1 is bypassed/disabled, TBI is always disabled.
